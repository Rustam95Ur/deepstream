Как запускать

Команду нужно выполнять в контейнере api. Там уже заданы адрес базы и адрес video-процесса, поэтому после правки камер пайплайн перечитывает конфиг. 

docker exec -it nexus-deepstream-api python -m app.cli status
docker exec -it nexus-deepstream-api python -m app.cli cameras list

-it нужен, когда пароль спрашивается в консоли. В скрипте передайте пароль флагом --password и вызывайте docker exec без интерактивного режима.

На машине разработчика, где уже выставлен NEXUS_DS_DATABASE_URL: 

poetry run python -m app.cli cameras list

Справка по группе: python -m app.cli cameras --help. Эта страница лежит в репозитории как docs/cli.html и открывается в браузере по адресу /cli.html, даже если Vue-консоль не собрана.

Не запускайте команды в контейнере video. Миграции через PgBouncer там некуда слать, а перезагрузка пайплайна не вызовется.

Общие флаги

ФлагЗачем
--jsonРезультат одним JSON. Ошибки тоже JSON, но в stderr. Ставится перед группой: --json cameras list.
--versionВерсия ноды.
--yesПодтверждение удаления и массовой отправки в вебхук. Без него эти команды ничего не делают.
--helpСправка по текущей команде. База для этого не нужна.

Код выхода 0 — успех, 1 — ошибка данных или базы, 2 — неверные аргументы, 130 — прервано с клавиатуры.

Камеры

Поток — это rtsp:// или file://. После создания, правки и удаления video-процесс получает reload.

Список и карточка

python -m app.cli cameras list
python -m app.cli cameras list --q калитка --enabled true
python -m app.cli cameras get cam_gate
ФлагЗачем
--qПоиск по id, имени и адресу.
--enabled true|falseТолько включённые или только выключенные.
--limit, --cursorСтраница. Если строк больше лимита, внизу будет курсор следующей.

Создать

python -m app.cli cameras add --id cam_gate --name "Калитка" --uri "rtsp://user:pass@10.0.0.12/stream1"
python -m app.cli cameras add --name "Запас" --uri rtsp://10.0.0.12/stream1 --disabled
python -m app.cli cameras add --name "Двор" --uri rtsp://10.0.0.20/stream --triggers presence,vif
ФлагЗачем
--uriОбязателен. Адрес потока.
--idСтабильный id. Если занят, команда остановится, а не перезапишет камеру.
--nameИмя. Пустое имя станет равным id.
--external-idid камеры в Campus.
--disabledСоздать выключенной. По умолчанию камера сразу включена.
--triggersСписок через запятую: presence, convergence, vif, stream_silent, fall, smoke. Без флага камера берёт типы ноды.
--no-triggersНа этой камере не запускать ни один тип.
--metaJSON-объект дополнительных полей, например {"fps":25,"resolution_width":1280}.

Изменить, включить, выключить, удалить

python -m app.cli cameras update cam_gate --name "Калитка запад" --uri rtsp://10.0.0.12/stream2
python -m app.cli cameras update cam_gate --inherit-triggers
python -m app.cli cameras enable cam_gate
python -m app.cli cameras disable cam_gate
python -m app.cli cameras delete cam_gate --yes

update меняет только переданные поля. --meta дописывает ключи к уже сохранённым. disable ждёт, пока камера уйдёт из пайплайна, до 15 секунд. delete без --yes не удаляет.

Пачка тестовых камер

python -m app.cli cameras test --uri rtsp://127.0.0.1:8554/cam1 --count 2

Создаёт test_1, test_2, … на один и тот же адрес, в пределах max_streams. --count от 1 до 128.

Отправить в вебхук

Та же кнопка, что в реестре камер: с текущего потока снимается ролик и ставится в очередь как инцидент на все включённые вебхуки. Одна камера или несколько id — выборочно. --all — весь реестр. Каждая камера ждёт свой ролик, поэтому пачка идёт по очереди и может занять заметное время. 

python -m app.cli cameras webhook cam_gate
python -m app.cli cameras webhook cam_gate cam_yard
python -m app.cli cameras webhook --all --enabled --yes
python -m app.cli cameras webhook --all --yes
ФлагЗачем
idОдин или несколько id. Повтор одного и того же id отправляется один раз.
--allВсе камеры реестра. Без --yes команда останавливается.
--enabledТолько вместе с --all: пропустить выключенные.

Если у части камер ролик не снялся, остальные всё равно отправляются. В конце строка готово: N из M. Код выхода 1, если хотя бы одна не ушла. С --json в ответе поля ok, failed и items.

Настройки ноды

Файл settings.json в каталоге данных. После записи video-процесс перечитывает конфиг. Полный список имён: settings keys.

python -m app.cli settings show
python -m app.cli settings keys
python -m app.cli settings set max_streams=8 node_name="Узел двор"
python -m app.cli settings set enable_clip_record=true cooldown_s=30
python -m app.cli settings set enabled_triggers=presence,convergence,vif,stream_silent
python -m app.cli settings set billing_api_key=XXXX --reveal
КлючСмысл
node_id, node_nameИдентификатор и имя ноды.
max_streamsСколько камер разбирать одновременно, от 1 до 128.
enable_clip_recordtrue / false. Вырезать ролик.
enable_http_sinkОтправлять события на webhook.
enabled_triggersТипы через запятую. none — выключить все на ноде.
clip_pre_s, clip_post_sСекунды ролика до и после события.
cooldown_sПауза перед повторным событием.
presence_min_people, presence_sustain_sПорог присутствия.
min_tracks, converge_dist_bh, sustain_sПорог схождения.
vif_iou_thresh, vif_sustain_sПорог пересечения.
stream_silent_sСколько секунд без кадров считать тишиной.
conf_threshold, infer_intervalДетектор: порог и каждый N-й кадр.
mux_width, mux_heightРазмер кадра в пайплайне.
auto_start_pipelineЗапускать разбор при старте video.
billing_url, billing_api_keyЛицензия. Смена ключа сразу запускает проверку.
trigger_thresholdsJSON с порогами по типам. Обычно хватает плоских ключей выше.

Булевы значения: true, false, yes, no, 1, 0, да, нет.

settings show прячет ключ лицензии. --reveal показывает его.

triggers_url только заготовка: при пустой таблице webhook API один раз создаёт запись из этого адреса на своём старте. Живые адреса задаются командой webhooks add.

Webhook

Сюда нода шлёт инциденты. Логин и пароль — это ещё и Basic-доступ, которым Campus читает и пишет камеры по HTTP. Пароль в списке не показывается, только факт, что он задан. 

python -m app.cli webhooks list
python -m app.cli webhooks add --name campus --url https://campus.example/api/v1/incidents/ --login node1 --password 'secret-pass'
python -m app.cli webhooks update WEBHOOK_ID --url https://campus.example/api/v1/incidents/ --retries 8
python -m app.cli webhooks disable WEBHOOK_ID
python -m app.cli webhooks enable WEBHOOK_ID
python -m app.cli webhooks delete WEBHOOK_ID --yes
ФлагЗачем
--urlАдрес, начинается с http:// или https://.
--loginОбязателен при создании. Двоеточие в логине нельзя.
--passwordМинимум 8 символов. Если флага нет, команда спросит дважды.
--nameКороткое имя. По умолчанию webhook.
--timeoutСекунды ожидания ответа, от 1 до 120. По умолчанию 5.
--retriesПовторы после ошибки, от 0 до 20. По умолчанию 5.
--disabledСоздать выключенным.

Пользователи консоли

Это вход в веб-интерфейс ноды, не учётная запись Campus. Пароль в список не попадает.

python -m app.cli users list
python -m app.cli users add --email operator@school.example --name "Оператор" --password 'long-pass'
python -m app.cli users get operator@school.example
python -m app.cli users update operator@school.example --password 'new-long-pass'
python -m app.cli users delete operator@school.example --yes

get, update и delete принимают id или email. Пароль короче 8 символов не сохранится. Без --password команда add спросит его и попросит повторить.

Статус

python -m app.cli status

Имя ноды, число камер, идёт ли разбор, первый включённый webhook и действительна ли лицензия.

Пайплайн

python -m app.cli worker status
python -m app.cli worker start
python -m app.cli worker stop
python -m app.cli worker reload

reload просит video заново прочитать камеры и настройки. Камеры и settings set делают это сами. В выводе видно, какие камеры не попали в разбор и почему: выключена, упёрлись в max_streams, пайплайн остановлен.

Лицензия

python -m app.cli billing status
python -m app.cli settings set billing_api_key=XXXX billing_url=https://billing.example/api/v1/public/keys/validate
python -m app.cli billing check
python -m app.cli billing check --key XXXX --url https://billing.example/api/v1/public/keys/validate

Сохраняет ключ только settings set. billing check проверяет текущий ключ, а --key и --url действуют на один запрос и в файл не пишутся.

Ответ stolen_key с требованием уничтожения останавливает контейнеры этого compose-проекта так же, как проверка из веба. Том с данными при этом остаётся.

История

python -m app.cli history triggers --limit 20
python -m app.cli history triggers --camera cam_gate --type presence
python -m app.cli history show EVENT_ID
python -m app.cli --json history show EVENT_ID
python -m app.cli history resend EVENT_ID
python -m app.cli history outbound --status dead
python -m app.cli history retry JOB_ID
python -m app.cli history sends --event EVENT_ID
КомандаЧто делает
triggersСработки. Фильтры --camera, --type, --event.
showОдно событие. Полный payload — с --json.
resendСнова ставит событие во все включённые webhook.
outboundОчередь доставки. Статусы: pending, retrying, dead, ok.
retryПовторить одно задание по его id из outbound.
sendsЖурнал уже сделанных HTTP-попыток.

--limit от 1 до 500, по умолчанию 20. Дальше — --cursor из нижней строки ответа.
